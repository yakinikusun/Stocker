# 冷蔵庫・在庫管理システム「Freezer」統合仕様書

## 1. システム概要

本システムは、個人および特定家庭・小規模グループにおける冷蔵庫・冷凍庫・野菜室・パントリー等の在庫管理を簡略化・効率化するためのクラウド型在庫管理Webアプリケーション（PWA）です。

- **アプリ名**: Freezer（フリーザー）
- **対象ユーザー**: 完全招待制・家庭内複数ユーザー（管理者 / 一般ユーザー）
- **主要アクセス機器**: スマホ（iOS / Android）および PC・タブレットブラウザ
- **設計方針**: セキュリティ（データ漏洩防止・改ざん防止）を最優先にしつつ、日常の運用の手間を最小化する。

### 対象および目的
- **目的**: 冷蔵庫・冷凍庫・野菜室、その他保管場所の在庫管理を簡略化・効率化するサービス。
- **対象**: 完全招待制により特定家族・グループのみが使用可能。主にスマホ・タブレット・PCでのアクセスを想定。
- **アカウントの種類**:
  - 管理者 (`admin`): マスタ変更・商品物理削除権限を保持。
  - 一般ユーザー (`member`): 在庫数量変更・追加・閲覧が可能。

## 2. スコープ

### 管理対象データ
1. **在庫状況 (`products`)**：商品ごとの現在数量、保管場所、タグ、商品画像
2. **履歴 (`stock_history`)**：在庫の増減操作ログ（誰が・いつ・何を・どの場所で・どれだけ変更したか）
3. **ユーザー認証情報 (`auth.users` / `profiles`)**：アカウント・権限（接続判定・削除権限）
4. **マスタ設定データ (`locations`, `tags`, `presets`)**：保管場所、分類タグ、再補充用プリセット

### MVPに含む機能
- 在庫の一覧表示・追加・数量変更・削除
- 画像ファイルアップロード（ドラッグ＆ドロップ / 画像プレビュー / Supabase Storage保存）
- 使われなくなった画像の自動削除（参照カウントチェックによるクリーンアップ）
- 操作履歴の記録・閲覧（改ざん不可な追記専用ログ、連続操作の自動圧縮表示）
- ユーザー認証・ログイン・権限管理（管理者 / 一般ユーザー）
- バーコードスキャンによる商品の特定・在庫更新（Webカメラ + ZXing）
- 保管場所の追加・編集・削除（冷蔵庫、冷凍庫、野菜室、パントリー等）
- 分類タグの追加・編集・削除（飲料、調味料、生鮮食品等）
- 在庫プリセットの登録・「在庫に追加」再呼び出し機能
- 検索・絞り込み機能（保管場所ごと・名前・タグ・二値在庫状態）
- PWA化（ホーム画面追加、アプリライクなUI）
- DevContainer（Docker開発環境対応）

### MVPに含まない機能（将来検討・後付け前提で設計）
- 画像認識による商品判定（優先度低、バーコードで代替できない商品のみの補助機能として将来検討）
- 自動発注・原価計算などの複雑なビジネスロジック（現時点で要件なし）

## 3. アーキテクチャ ＆ 採用理由

```
[スマホ (iOS/Android) / PC ブラウザ / PWA]
        ↓ HTTPS (Cloudflare Pages ホスティング想定)
[Vite + React 19 + TypeScript (SPA)]
        ↓ @supabase/supabase-js SDK / LocalStorage Fallback
[Supabase Backend]
  ├─ PostgreSQL（在庫・履歴・ユーザー・マスタデータ）
  ├─ Storage (product-images バケット - 商品画像ファイル保存)
  ├─ Auth（セッション管理）
  ├─ Row Level Security（アクセス制御 ＆ 改ざん防止）
  ├─ Realtime（複数人での同時利用時のリアルタイム反映）
  └─ Edge Functions（カスタムロジックが必要な場合のみ）
```

### 採用理由・決定事項
- **独自バックエンドサーバーは作らない**：SupabaseがDB・認証・API・ストレージを兼ねるため、フロントから直接呼び出すだけで完結する。
- **VPN（Tailscale等）は使わない**：Cloudflare Pages + Supabaseはどちらも公開HTTPSエンドポイントを持つため、VPN経由でなくても安全にアクセスできる。認証とRow Level Securityでアクセス制御する。
- **KVではなくPostgreSQL（Supabase）を使う**：在庫数量は正確性が重要なデータのため、結果整合性のあるKVストアではなく、ACID特性を持つリレーショナルDBを採用。
- **画像ストレージの活用**: オブジェクトストレージ (Supabase Storage) を採用し、DBには画像URLのみを保持。参照されなくなった画像は自動的に物理削除される。
- **クレジットカード登録不要**：Cloudflare Pages・Supabaseともに無料枠で利用可能。
- **SSR/Next.jsは不要**：社内・家庭内ツール的性質でSEO要件がないため、Vite + React の SPA構成とする。

## 5. データモデル (テーブル ＆ ストレージ構造)

### 5.1 `locations`（保管場所マスタ）
| カラム | 型 | 備考 |
|---|---|---|
| id | uuid | PK |
| name | text | 保管場所名（例: 冷蔵庫、冷凍庫、野菜室、パントリー） |
| created_at | timestamptz | 作成日時 |

### 5.2 `tags`（分類タグマスタ）
| カラム | 型 | 備考 |
|---|---|---|
| id | uuid | PK |
| name | text | タグ名（例: 飲料、調味料、乳製品、冷凍食品、生鮮食品） |
| color | text | カラーコード |
| created_at | timestamptz | 作成日時 |

### 5.3 `presets`（在庫プリセットマスタ）
| カラム | 型 | 備考 |
|---|---|---|
| id | uuid | PK |
| jan_code | text | バーコード値（任意） |
| name | text | 商品名 |
| image_url | text | 画像URL（Supabase StorageまたはBase64） |
| location | text | 初期保管場所 |
| tags | text[] | タグ配列 |
| created_at | timestamptz | |
| updated_at | timestamptz | |

### 5.4 `products`（商品マスタ）
| カラム | 型 | 備考 |
|---|---|---|
| id | uuid | PK |
| jan_code | text | バーコード値（UNIQUE） |
| name | text | 商品名 |
| image_url | text | 画像URL（Supabase StorageまたはBase64） |
| current_stock | integer | 現在数量 (>= 0) |
| location | text | 保管場所（例: 冷蔵庫） |
| tags | text[] | タグ配列 |
| created_at | timestamptz | |
| updated_at | timestamptz | |

### 5.5 `stock_history`（操作履歴ログ・追記専用・連続操作自動圧縮対応）
| カラム | 型 | 備考 |
|---|---|---|
| id | uuid | PK |
| product_id | uuid | FK → products |
| user_id | uuid | FK → auth.users |
| change_amount | integer | 増減値 (+/-) |
| reason | text | 任意（例: 入荷、出庫、棚卸修正など） |
| created_at | timestamptz | 記録日時 |

※ **連続ログの自動圧縮仕様**:
同一ユーザーが同一商品に対し、同一理由で10分以内に連続して増減操作を行った場合（例: `+1` を連続3回クリック）、独立した複数ログではなく、1つの合算ログ（例: `+3`・`3回合算`）として自動圧縮・集約されます。

### 5.6 Supabase Storage (`product-images` バケット)
- 商品およびプリセット用画像を保存する公開ストレージバケット。
- **自動クリーンアップ**: レコード削除時に他の商品・プリセットから参照されていない画像ファイルをストレージから自動削除。

## 6. 在庫量判定仕様

在庫数量の判定は **二値判定（バイナリ）** に統一されています。

1. **在庫あり (`in_stock`)**: `current_stock > 0`
   - ステータスバッジ: 「在庫あり (個数)」
2. **在庫切れ (`out_of_stock`)**: `current_stock === 0`
   - ステータスバッジ: 「在庫なし」

## 7. セキュリティ要件

- **認証管理**: パスワードはSupabase Auth標準機能によりハッシュ化・管理（自前実装しない）。
- **Row Level Security (RLS)**:
  - ログインユーザーのみ全テーブルの読み書きが可能。
  - `stock_history` テーブルは **UPDATE / DELETE を許可しない** RLS ポリシーを設定（ログ改ざん防止）。
  - 管理者 (`admin`) のみ `products` テーブルのレコード削除が可能。
  - ストレージバケット `product-images` に対するアップロード・閲覧 RLS ポリシーを定義。
- **通信暗号化**: 通信は全て HTTPS（Cloudflare Pages / Supabase ともに標準対応）。
- **カメラセキュリティ**: Webカメラ（バーコードスキャン）は HTTPS 環境でのみ動作。

## 8. 画面構成およびUI/UX仕様

### UIデザインイメージ
- **基調**: 白と灰色をベースとした簡素・清涼感のあるデザイン。
- **アニメーション**: 最小限の演出で軽量・レスポンシブな操作性を重視。

### レスポンシブレイアウト
- **PC表示 (`md:` 768px以上)**: ヘッダー左側にロゴ、右側に主要画面移動タブを表示。
- **スマホ表示 (768px未満)**: ヘッダーはロゴのみ表示、画面下部に固定ボトムナビゲーションバーを配置。

### 画面一覧
1. **メイン画面 (在庫一覧)**:
   - 保管場所別ピルフィルター (`全て`, `冷蔵庫`, `冷凍庫`, `野菜室`, `パントリー` 等)
   - 検索機能 (商品名・JANコード・タグ・保管場所)
   - 二値ステータスフィルターおよびタグ絞り込み
   - 表示切替 (カード表示 / リスト表示)
   - 在庫増減クイック操作 (+1 / -1) ＆ 数量・理由詳細変更モーダル
2. **在庫設定画面 (マスタ管理)**:
   - 保管場所一覧の確認・追加・削除
   - 在庫プリセット一覧の確認・追加・削除・「在庫に追加」ワンタップ補充（画像アップロード対応）
   - タグ一覧の確認・追加・削除
3. **操作履歴画面 (監査ログ・自動圧縮)**:
   - 誰が・いつ・どの保管場所で・どの商品をどれだけ変更したかの全履歴ログを表示。
   - 連続する同一操作（同一商品・同一ユーザー・同一理由）は自動的に合算され、`X回合算` バッジが表示されます。
4. **アカウント設定画面**:
   - アカウント情報の編集、ログアウト
   - ユーザー権限 (`admin` / `member`) 切替
   - Supabase接続設定 (URL / Anon Key) ＆ デモデータリセット

## 9. 将来拡張の余地（設計時に考慮）

- **商品情報の自動補完**: バーコード読み取り時、外部の商品検索API（楽天商品検索API等）と連携して商品名・画像を自動取得する拡張が可能。Supabase Edge Functions経由で実装想定。
- **画像認識による商品判定**: 将来必要になった場合、Edge Functionsから外部の画像認識APIを呼び出す形で後付け可能。既存構成を崩さずに追加できる設計とする。

---

## 10. 非スコープ・明示的に採用しない技術

- Tailscale / WireGuard 等のVPN
- 独自VPS（Oracle Cloud等）でのセルフホスト
- Next.js（SSR不要のため）
- Cloudflare KV（在庫数量の整合性要件を満たさないため）
- ネイティブアプリ（iOS/Android別開発）：PWAで代替
