# 冷蔵庫・在庫管理システム「Freezer」仕様書

## 1. システム概要

本システムは、個人および特定家庭・小規模グループにおける冷蔵庫・冷凍庫・野菜室・パントリー等の在庫管理を簡略化・効率化するためのクラウド型在庫管理Webアプリケーション（PWA）です。

- **アプリ名**: Freezer（フリーザー）
- **対象ユーザー**: 完全招待制・家庭内複数ユーザー（管理者 / 一般ユーザー）
- **主要アクセス機器**: スマホ（iOS / Android）および PC・タブレットブラウザ
- **設計方針**: セキュリティ（データ改ざん防止・漏洩防止）を最優先しつつ、日常の運用の手間を最小化する。

---

## 2. アーキテクチャ ＆ 技術スタック

本システムは独自バックエンドサーバーを保持せず、フロントエンドから直接マネージドサービス（Supabase）を呼び出すサーバーレス構成を採用しています。

```
[スマホ / PC ブラウザ / PWA]
        ↓ HTTPS (Cloudflare Pages ホスティング想定)
[Vite + React 19 + TypeScript (SPA)]
        ↓ @supabase/supabase-js SDK / LocalStorage Fallback
[Supabase Backend]
  ├─ PostgreSQL（在庫・履歴・保管場所・プリセット・タグ・ユーザーデータ）
  ├─ Auth（セッション管理）
  └─ Row Level Security（アクセス制御 ＆ 改ざん防止）
```

## 3. データモデル (テーブル構造)

### 3.1 `locations`（保管場所マスタ）
| カラム | 型 | 備考 |
|---|---|---|
| id | uuid | PK |

| カラム | 型 | 備考 |
|---|---|---|

| name | text | タグ名（例: 飲料、調味料、乳製品、冷凍食品、生鮮食品） |
| color | text | カラーコード |
| created_at | timestamptz | 作成日時 |

### 3.3 `presets`（在庫プリセットマスタ）
| カラム | 型 | 備考 |
|---|---|---|
| id | uuid | PK |
| jan_code | text | バーコード値（任意） |
| name | text | 商品名 |
| image_url | text | 画像URL（任意） |
| location | text | 初期保管場所 |
| tags | text[] | タグ配列 |
| created_at | timestamptz | |
| updated_at | timestamptz | |

### 3.4 `products`（商品・在庫マスタ）
| カラム | 型 | 備考 |
|---|---|---|
| id | uuid | PK |
| jan_code | text | バーコード値（UNIQUE） |
| name | text | 商品名 |
| image_url | text | 画像URL（任意） |
| current_stock | integer | 現在数量 (>= 0) |
| location | text | 保管場所（例: 冷蔵庫） |
| tags | text[] | タグ配列 |
| created_at | timestamptz | |
| updated_at | timestamptz | |

### 3.5 `stock_history`（操作履歴ログ・追記専用・連続操作自動圧縮対応）
| カラム | 型 | 備考 |
|---|---|---|
| id | uuid | PK |
| product_id | uuid | FK → products |
| user_id | uuid | FK → auth.users |
| change_amount | integer | 増減値 (+/-) |
| reason | text | 操作理由（入荷、出庫、棚卸修正など） |
| created_at | timestamptz | 記録日時 |

※ **連続ログの自動圧縮仕様**:
同一ユーザーが同一商品に対し、同一理由で10分以内に連続して増減操作を行った場合（例: `+1` を連続3回クリック）、独立した複数ログではなく、1つの合算ログ（例: `+3`・`3回合算`）として自動圧縮・集約されます。

## 4. 判定ロジック仕様

### 在庫量の判定仕様
在庫状態の判定は以下の **二値判定（バイナリ）** に統一されています。

1. **在庫あり (`in_stock`)**: `current_stock > 0`
   - 緑色のステータスバッジ「在庫あり (個数)」を表示。
2. **在庫切れ (`out_of_stock`)**: `current_stock === 0`
   - 赤色の点滅バッジ「在庫なし」を表示。

## 5. 画面構成および機能仕様

### 5.1 メイン画面 (在庫一覧)
- **保管場所フィルター**: タップで指定の保管場所の在庫のみを抽出。
- **マルチ条件検索**: 商品名・JANコード・保管場所名・タグ名でのリアルタイム検索。
- **二値フィルター**: 在庫あり / 在庫切れのフィルター。
- **表示切り替え**: カード表示とリスト表示の切り替え。
- **クイック操作**: 各商品カードから直接「+1 (追加)」「-1 (消費)」操作。

### 5.2 在庫設定画面 (マスタ管理)
- **保管場所一覧**: 保管場所の追加・一覧確認・削除。
- **在庫プリセット一覧**: プリセットの登録・「在庫に追加」ワンタップ補充。
- **タグ一覧**: 分類用タグの追加・一覧確認・削除。

### 5.3 操作履歴画面 (監査ログ・自動圧縮)
- 誰が・いつ・どの保管場所で・どの商品をどれだけ変更したかの全履歴ログを表示。
- 連続する同一操作（同一商品・同一ユーザー・同一理由）は自動的に合算され、`X回合算` バッジが表示されます。

### 5.4 アカウント設定画面
- ユーザー情報の確認・編集、権限（管理者 / 一般ユーザー）切替。
- Supabase接続設定 (URL / Anon Key) ＆ デモデータリセット。
